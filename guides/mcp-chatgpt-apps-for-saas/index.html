Guide · MCP and ChatGPT apps

How ChatGPT, Claude and other agents can use your product.

In-product agents, MCP servers and ChatGPT apps: what each is for, how to choose, and what to design before you build.

About this guide: a practical overview for SaaS and e-commerce product teams. Platform facts are linked to official documentation; recommendations are Frontier Labs' point of view. Published 17 November 2026.

Three ways agents can reach your product

1 · Inside

An agent in your product

Your own conversational or voice experience calls your back end through tools. You control the interface, the model and the data flow.

2 · Tools

An MCP server

The Model Context Protocol is an open standard for connecting AI assistants to external tools and data. An MCP server exposes chosen product capabilities as tools that MCP-capable assistants, such as ChatGPT and Claude, can call.

3 · App

A ChatGPT app

OpenAI's Apps SDK lets developers design both the logic and the interface of an app that runs inside ChatGPT, and it is built on the Model Context Protocol. Apps are listed through a separate submission flow.

Foundation

A clean API

All three depend on APIs with clear authentication, permissions and error handling. Agents need small, well-described operations more than broad endpoints.

How to choose

  • Start inside your product when the workflow needs your data, your UI and tight control of the experience.
  • Add an MCP server when customers already work in ChatGPT, Claude or other assistants and want your product's capabilities there.
  • Build a ChatGPT app when the task needs a visual interface inside the conversation (a list, a chart, a form) and ChatGPT is where your users are.

Many products end up with all three, sharing one set of well-designed tools.

Design checklist

  1. Pick one workflow with a clear outcome, not “add AI”.
  2. Inherit your permission model: an agent acts for a signed-in user and reaches only what that user can.
  3. Decide the autonomy level per step: suggest, act with approval, or act and report.
  4. Make tools small and descriptive, with typed inputs, clear errors and safe retries.
  5. Design recovery: how a user undoes or corrects what an agent did.
  6. Log tool calls and outcomes, and define test cases before launch.
  7. Decide when the conversation should hand people back to your product.
